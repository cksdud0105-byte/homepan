# Windows 전용 브라우저로 입력·발행하기

Homepan이 여는 별도 Chromium 프로필에 직접 로그인하는 방식입니다. 일반 크롬의 프로필·쿠키를 가져오지 않습니다. 프로그램은 본인 PC에서 실행하며 클라우드에 로그인 세션을 업로드하지 않습니다.

**현재 상태:** 브라우저 실행, 화면 요소 연결, 서식 붙여넣기, 이미지 첨부, 읽기 결과 비교, 명시적인 발행, 비로그인 공개 페이지 확인을 구현했습니다. 실제 Chromium의 합성 편집 화면에서 테스트했습니다. Windows 및 실제 네이버 스마트에디터의 동작 검증은 아직 하지 않았습니다. 네이버가 붙여넣기 서식을 바꾸거나 사진 메뉴 구조가 다르면 중단하며, 첫 실제 화면 확인 후 어댑터 조정이 필요할 수 있습니다.

이 버전은 사람이 옆에서 확인하는 **반자동 방식**입니다. 대상 블로그/초안 열기, 첫 화면 요소 지정, 태그·카테고리·대표 이미지 설정, 최종 발행 확인은 사용자가 수행합니다. 사진 첨부 후 커서가 본문으로 돌아오지 않으면 위치를 직접 지정하도록 안내합니다. 무인 예약·대량 발행·탐지 우회 기능은 없습니다.

## 1. 설치

Windows 사용자 계정으로 실행합니다. 관리자 실행은 필요하지 않습니다. Python 3.11 이상과 Git이 필요합니다.

PowerShell에서 처음 내려받는 경우:

```powershell
git clone https://github.com/cksdud0105-byte/homepan.git C:\Projects\homepan
cd C:\Projects\homepan
.\scripts\setup-windows.cmd
```

이미 내려받았다면 해당 폴더에서 `git pull` 후 설치 스크립트를 실행합니다. `setup-windows.cmd`를 탐색기에서 두 번 클릭해도 됩니다. Python Launcher의 `py` 명령이 없다면 Python 설치 상태를 먼저 확인합니다.

설치 스크립트는 저장소 안의 `.venv`에 브라우저용 패키지를 설치하고 Playwright의 Chromium을 받습니다. 운영체제의 전역 실행 정책, 프록시, TLS 검증 설정을 변경하지 않습니다. 패키지 다운로드에 실패하면 오류를 확인한 뒤 재실행하며, 일반 브라우저 프로필을 복사해 해결하지 않습니다.

## 2. 직접 로그인

```powershell
.\scripts\login-windows.cmd
```

또는:

```powershell
.\scripts\browser-windows.cmd login
```

프로그램이 연 창에서 직접 네이버에 로그인합니다. 비밀번호·2단계 인증·CAPTCHA는 직접 입력합니다. 로그인이 끝나면 터미널에서 Enter를 눌러 정상 종료합니다. 비밀번호나 쿠키를 채팅·파일 첨부로 보내지 않습니다.

기본 보관 위치:

```text
%LOCALAPPDATA%\Homepan\
  browser\                 전용 브라우저 프로필 (민감한 로그인 상태)
  editor.json              직접 지정한 화면 요소와 블로그 ID
  publications.sqlite3     이 PC의 공통 발행 기록
  session.lock             동시 실행 차단
```

다른 브라우저에서 로그인한 것은 이 프로필에 연결되지 않습니다. 클라우드 PC나 다른 PC로 이 폴더를 복사하지 않습니다. 다른 Windows 사용자·관리자·악성코드로부터의 완전한 격리나 암호화를 이 프로그램이 보장하지는 않습니다.

상태 확인:

```powershell
.\scripts\browser-windows.cmd status
```

프로필이 존재하는 것과 로그인이 유효한 것은 다릅니다. 실제 로그인 상태는 창을 열어 확인해야 합니다.

## 3. 실제 편집 화면 연결

```powershell
.\scripts\browser-windows.cmd calibrate --blog-id 내블로그ID
```

`내블로그ID`는 블로그 주소 `https://blog.naver.com/내블로그ID`의 ID로 바꿉니다. 본인 블로그에서 **새 빈 글쓰기**를 연 뒤 터미널에서 Enter를 누릅니다.

화면 안내에 따라 순서대로 선택합니다.

1. 빈 제목 입력란.
2. 빈 본문 입력란.
3. 제목·툴바를 제외하고 본문과 앞으로 넣을 사진을 모두 담는 전체 영역. 마우스로 가리킨 후 ↑ 키로 상위 영역을 선택할 수 있습니다.
4. PC의 파일 선택창을 직접 여는 사진 버튼.

선택 중인 버튼 클릭은 차단되며 요소만 기록합니다. Esc는 취소입니다. 셀렉터는 실제 선택한 DOM에서 추출하며 비밀번호·본문·쿠키·화면 덤프를 저장하지 않습니다.

제목과 본문이 프레임 안에 있어도 지원합니다. 화면이 바뀌거나 저장된 요소가 중복/소실되면 자동으로 다른 버튼을 추측하지 않고 멈춥니다. 사진 버튼이 하위 메뉴/다중 창을 거쳐야 하거나 편집기의 요소 ID가 매번 바뀌면 추가 어댑터 조정이 필요합니다.

## 4. 클라우드 원고를 PC로 가져오기

먼저 기존 스킬로 style~factcheck 단계를 완료합니다. 원고, 이미지, 검증 리포트만 다음 명령으로 ZIP에 담습니다.

```bash
python -m homepan export runs/first-post exports/first-post.zip
```

이 ZIP을 PC로 내려받고 프로젝트 폴더에서 압축을 풉니다.

```powershell
Expand-Archive -LiteralPath .\first-post.zip -DestinationPath .\runs\first-post
.\.venv\Scripts\python.exe -m homepan validate runs/first-post factcheck
```

ZIP 안의 `run.json`은 `runs/first-post/run.json` 위치에 있어야 합니다. 이미 있는 실행 폴더에 덮어쓰지 않습니다. ZIP은 실행에 필요한 허용 목록의 파일만 포함하며 세션·쿠키·프로필·발행 DB는 포함하지 않습니다. 검증 일시는 갱신하지 않으므로 조사 48시간/팩트체크 24시간이 지나면 실제 재검토가 필요합니다.

## 5. 먼저 입력·검토만 실행

```powershell
.\scripts\browser-windows.cmd write runs/first-post
```

프로그램이 연 창에서 새 빈 원고를 선택합니다. 제목·본문·표·소제목을 입력하고 사진을 한 장씩 첨부합니다. 클립보드는 현재 문단/캡션으로 교체되며 이전 내용은 복원하지 않습니다. 기존 클립보드 내용은 읽지 않습니다.

자동으로 검사하는 내용:

- 제목 및 본문 텍스트가 확정 원고와 일치하는지.
- 이미지 개수와 본문 안 삽입 위치가 일치하는지.
- HTML 표·소제목 구조가 유지되는지.
- 업로드가 완료되고 이미지가 로드되는지.

사용자가 확인·설정하는 내용:

- 실제 이미지 내용·순서·캡션·출처·서식.
- 카테고리, 정확히 10개 태그, 첫 이미지의 대표 지정.
- 플랫폼이 대체 텍스트를 지원하면 alt_text 설정.

맞으면 터미널에 `검토완료`를 입력합니다. `write` 기본 명령은 발행하지 않습니다. 종료 전 브라우저에서 임시저장 상태를 직접 확인합니다. 자동 임시저장 성공을 추정하지 않습니다.

중간에 멈추면 `browser_progress.json`을 보존합니다. 같은 실행을 `write`로 반복하지 않으며, 기존 초안을 먼저 확인합니다. 부분 입력된 글은 브라우저에서 보완해 확정 원고와 일치시킨 다음 `review`로 다시 검사할 수 있습니다.

```powershell
.\scripts\browser-windows.cmd review runs/first-post
```

`review`는 기존 초안을 다시 열어 대조할 뿐 원고를 재입력하지 않습니다.

## 6. 검토 후 즉시 발행

기존 초안을 열어 확인한 뒤 발행하는 경우:

```powershell
.\scripts\browser-windows.cmd review runs/first-post --publish
```

처음부터 입력·검토·발행을 한 번에 진행할 때는 `write runs/first-post --publish`를 사용합니다.

1. 제목·본문 대조 및 사용자의 `검토완료` 확인.
2. 직접 발행 옵션을 열어 대상 블로그, 전체 공개, 즉시 발행을 확인.
3. 실제 최종 발행 버튼을 화면에서 지정. 이때는 클릭하지 않습니다.
4. 터미널에 `발행`을 입력하면 DB에 예약을 남긴 뒤 해당 버튼을 **한 번만** 클릭.
5. 새 게시물 URL 확인 후, 로그인 정보를 공유하지 않는 별도 확인 창에서 제목·본문 영역을 지정.
6. 공개된 내용·이미지를 확인하고 `공개확인`을 입력하면 발행 완료 기록.

예약 발행은 이 CLI에서 지원하지 않습니다. 네이버 공개 페이지가 편집기와 다른 소제목/표 표현을 사용하여 자동 비교에 실패하면 글은 이미 발행되었을 수 있습니다. 새 글을 만들지 말고 원격 게시 목록을 먼저 확인합니다.

## 7. 실패·재개

- 접근 제한, 로그인/보안 인증 요소, 401/403/429 문서 응답, UI 변경, 업로드 실패 시 중단합니다. 모든 종류의 보안 화면을 자동 판별할 수 있는 것은 아닙니다.
- 실패해도 브라우저를 바로 닫지 않고 기존 원고/게시 여부를 확인할 시간을 줍니다. 프로그램을 강제 종료하면 이 단계가 생략될 수 있습니다.
- 글이 이미 발행됐는데 완료 기록만 남지 않은 경우:

```powershell
.\scripts\browser-windows.cmd recover runs/first-post --url "https://blog.naver.com/내블로그ID/게시물번호"
```

`recover`는 비로그인 공개 페이지를 확인하고 기존 예약을 완료하며 발행 버튼을 누르지 않습니다. 기록 유효기간이 지났다면 실제 재검토가 필요합니다. `pending` DB 기록을 지워 자동 재발행하지 않습니다.

브라우저 도구는 `%LOCALAPPDATA%\Homepan\publications.sqlite3`를 공통 DB로 사용합니다. 기존 코어 CLI로 직접 reserve/record할 때도 `--db`로 **같은 DB**를 지정해야 합니다. 다른 DB나 다른 PC는 중복 기록을 공유하지 않습니다.

## 세션 종료와 보호

사용 후 전용 창을 정상 종료합니다. 계정 접근을 끊으려면 `login`으로 열어 직접 로그아웃하고 네이버의 로그인 기기/세션 관리에서도 확인하세요. 프로필 파일 삭제만으로 서버의 기존 세션이 폐기된다고 가정하지 않습니다.

세션 폴더는 Git 밖에 두며 OneDrive·Dropbox 같은 동기화 폴더에 옮기지 않습니다. 프로그램은 쿠키 내보내기, 외부 제어 포트, 스크린샷/네트워크 추적 자동 저장, 사용자 에이전트 위장, 가짜 오타, IP 회전 등을 사용하지 않습니다.

본인 PC의 평소 네트워크에서 실행해도 새 브라우저 보안 확인이나 자동화 제한이 발생할 수 있습니다. 네이버의 정상 이용 조건과 계정 안내를 따르고, 제한 안내가 뜨면 반복 실행하지 않습니다.

## 개발 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

브라우저 추가 패키지가 없으면 브라우저 테스트는 skipped로 표시됩니다. 브라우저 테스트는 네트워크 요청을 합성 페이지로 가로채며 실제 네이버에 접속하지 않습니다. Windows 설치 스크립트와 Windows 파일 잠금은 실제 Windows에서 최종 확인해야 합니다.

macOS/Linux 개발용 설치는 `python -m venv .venv`, 해당 가상환경의 Python으로 `pip install -e '.[browser]'`, `python -m playwright install chromium`을 실행합니다. 일반 사용자 PC에서 실행하며 클라우드 로그인용으로 사용하지 않습니다.
