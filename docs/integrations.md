# 실제 연동 상태와 한계

## 구현한 범위

- 8개 독립 SKILL.md: 입력·수행·출력·실패·재개 절차.
- Python 표준 라이브러리 CLI: 실행 생성, 스타일 통계, 단계 검증, 해시 고정, 단계 되돌리기, 에디터 계획, 발행 예약·기록.
- 로컬 SQLite: 동일 실행/원고의 중복 예약 차단, 네이버 게시물 URL 정규화, 재기록의 멱등성.
- 실제 원고가 검증을 통과해야 에디터 계획을 생성하는 게이트.
- Windows용 설치·실행 스크립트, 저장소 밖 전용 브라우저 프로필, 직접 로그인, 실제 화면 요소 연결.
- 로컬 브라우저의 서식 붙여넣기·파일 업로드·읽기 결과 비교, 사용자 검토 후 한 번 발행, 비로그인 공개 페이지 확인.
- PC 전달용 원고 ZIP 내보내기. 로그인 세션은 포함하지 않음.

2026-10-18 (Asia/Seoul) 다음 읽기 전용 문서 요청이 `Tunnel connection failed: 403 Forbidden`으로 실패했습니다.

- `https://developers.naver.com/docs/serviceapi/search/blog/blog.md`
- `https://developers.naver.com/docs/login/blog-api/blog-api.md`

이는 이 환경의 접근 실패이며 API의 존재·폐지·쓰기 지원 여부를 입증하지 않습니다. 검색 API가 글쓰기 API를 제공한다고 가정하지 않았습니다. 접근 차단을 우회하거나 미확인 엔드포인트를 코드에 넣지 않았습니다.

실제 연동 단계에서 네트워크 설정에 `developers.naver.com`, `blog.naver.com`, `m.blog.naver.com`을 검토하고, 로그인/이미지 호스트는 브라우저가 실제로 요구하는 대상을 확인해 추가합니다. 이 문서는 네트워크 설정을 자동 변경하지 않습니다. 사용자 비밀번호/쿠키를 채팅으로 받지 않습니다.

## 네이버 브라우저 연결 후 검증 기준

1. 브라우저를 연결하고 사용자가 직접 로그인합니다. CAPTCHA/2FA는 사용자가 처리합니다.
2. 실제 스마트에디터 UI에서 안정적인 접근성 선택자와 프레임 구조를 확인합니다.
3. 기존 글을 건드리지 않는 새 초안에서 제목, 문단, 소제목, 볼드, 2~3열 표, 이미지, 캡션을 각각 검증합니다.
4. editor_plan의 순서를 적용하고 실제 DOM/화면과 최종 원고를 비교합니다.
5. 업로드 타임아웃, 부분 입력, 중복 클릭, 로그인 만료를 테스트합니다. 무조건 전체 재입력하지 않습니다.
6. 사용자 발행 지시가 있는 실제 글에서 공개/예약 옵션을 확인하고 URL과 본문을 대조합니다.
7. 화면 캡처·선택자·스크린샷에 로그인 정보나 개인정보가 들어가지 않게 합니다.

최소 위 검증 전까지 네이버 실발행 연동이 검증됐다고 표시하지 않습니다. 지금 구현한 연결 도구는 사용자가 실제 화면에서 지정한 DOM만 사용하며 네이버 전용 CSS 선택자를 추정해 내장하지 않습니다. 실제 편집기의 서식·업로드 처리 방식이 다르면 중단 후 추가 조정이 필요합니다. Windows 사용 절차는 [전용 브라우저 안내](windows-browser.md)를 참조하세요.

## 원문 요구 중 조정한 내용

- “CTR 지수” → 확률이 아닌 근거 있는 편집 우선순위 점수.
- “정확한 말투 비율” → 측정 단위·표본·한계를 밝힌 휴리스틱 통계와 직접 검토.
- “미세 크롭으로 고유 이미지” → 권리가 확인된 이미지와 의미 있는 편집.
- “무결점·오류 0건” → 주장별 검토, 미해결 항목 차단, 검토 유효기간.
- “사람처럼 입력해서 탐지 완벽 우회” → UI 상태에 맞는 안정적인 입력, 우회 보장 없음.
- “고정 골든타임” → 사용자 시간대와 실제 성과 데이터에 따른 예약.
